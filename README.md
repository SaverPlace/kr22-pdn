## Реализованный метод

RuBERT распознаёт имена и фамилии. Параметр `aggregation_strategy="first"` объединяет части распознанных слов. GLiNER не используется. Для структурированных реквизитов применяются регулярные выражения, контекстные признаки, проверки формата и контрольных чисел.

Обязательные типы: NAME, SURNAME, INN, PASSPORT, CARD, OGRNIP, IP, EMAIL, BIRTH_CERT, KLADR.

Синонимическое обезличивание заменяет найденные значения данными того же типа. Для имён и фамилий используется pymorphy3 и контекстное определение грамматических признаков. Словарь соответствий обеспечивает согласованные замены повторов в пределах обработки. Если надёжная замена невозможна, используется резервный маркер; такие случаи отдельно учитываются в результатах.

Основные функции после выполнения ячеек с определениями:

```python
entities = recognize_pdn("Саша пришла на работу. E-mail: sample@example.org.")
new_text, entities = anon("Саша пришла на работу. E-mail: sample@example.org.", on_error="redact")
```

## Оценка

Проверочный набор создаётся в блокноте: синтетические примеры и встроенные фрагменты factRuEval-2016. Считаются Precision, Recall и F1 по каждому из десяти атрибутов, а также Macro и Weighted. Отдельно оцениваются точные границы целых сущностей и BIO-разметка токенов.

BERTScore сравнивает с исходным текстом синонимическую замену и маскирование. Для этой метрики дополнительно скачивается `bert-base-multilingual-cased`. Это отдельная модель оценки, а не обученная модель распознавания. В независимом запуске значения BERTScore могут отличаться из-за случайного выбора замен.

Ограничения исходной реализации сохранены: длинные тексты требуют предварительного разбиения; пропущенные детектором сущности не обезличиваются; для ИНН контрольные разряды пересчитываются, а не сохраняются буквально. Набор данных преимущественно синтетический. Согласованность повторов не означает неизменность результата при повторной обработке уже обезличенного текста.
